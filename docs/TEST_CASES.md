# 行為驗收案例（Gate 1 草案）

狀態：**Draft / 尚未核准、尚未執行**。本文件由 QA 角色依題目 B、使用者 WORKFLOW 與規劃中的 v1 契約獨立提出。以下預期是審核提案，不能視為使用者已決定。Gate 1 通過後，QA 依定稿 SPEC 編寫測試；Dev 不得修改測試。

## 驗證策略

- Vitest：資料驗證、正規化、價格規則、儲存讀寫與 migration。
- Playwright：真實 Custom Elements lifecycle、Shadow DOM、操作、跨頁同步與獨立嵌入。
- 截圖與人工檢視：對照提供的 momo 截圖確認兩種卡片的資訊層級，不能以測試通過代替畫面驗收。
- P0 為必要交付；P1 為擴充及韌性。測試以可見行為與公共 API 為準，不依賴第幾個節點或內部 class 名稱。

## 資料與純函式

| ID | 優先 | 情境 | 預期行為（待 Gate 1 定稿） |
|---|---|---|---|
| D01 | P0 | 最小合法 v1 商品 | 必填資料通過驗證；可顯示圖片、名稱、售價；選填欄位缺少不出現 undefined、空徽章或空連結。 |
| D02 | P0 | 缺少 id、title、image 或 price；未知版本 | 回傳可定位欄位的錯誤；不保存不合法資料、不使其他卡片崩潰。 |
| D03 | P0 | price 為 0、負數、NaN、Infinity 或數字字串 | 0 為合法價格；其餘不合法值依契約拒絕，不默默轉成另一金額。 |
| D04 | P0 | price 為 43900 | 依新台幣呈現 $43,900；格式化不改寫來源數值。小數規則需 SPEC 明定後補測。 |
| D05 | P0 | originalPrice 缺少、等於或小於 price | 不顯示劃線價與計算折扣；tagline 活動文案仍可獨立顯示。 |
| D06 | P0 | originalPrice 大於 price | 顯示劃線原價；折扣若列入範圍，須依核准公式及捨入規則驗證，不把促銷文案當計算結果。 |
| D07 | P0 | stock 缺少、0、正整數、負數或小數 | 缺少不顯示庫存；0 顯示售完且禁止購買動作；正整數顯示剩餘量；其餘拒絕。 |
| D08 | P0 | 不支援的 variant、badge 類型 | 可預期的驗證錯誤或核准 fallback；不靜默選取錯誤變體。 |
| D09 | P0 | title/tagline 含 HTML 或 script 片段 | 作為純文字呈現，沒有腳本執行或注入的互動元素。 |
| D10 | P0 | URL 為 HTTPS、相對路徑、javascript: 或非允許協定 | 接受契約允許的 URL；拒絕危險協定，包括前置空白及大小寫變化，不形成可執行連結。 |
| D11 | P1 | 多張商品具有重複 id | 回報重複鍵問題，不能編輯甲卡卻更新乙卡。 |

## 卡片與公開 API

| ID | 優先 | 情境 | 預期行為 |
|---|---|---|---|
| C01 | P0 | ranking 變體 | 圖片與資訊橫向配置；名稱、活動文案、售價及有效原價符合資料。 |
| C02 | P0 | flash-sale 變體 | 圖片、文案與價格縱向配置；顯示選填徽章、庫存與搶購動作。 |
| C03 | P0 | 長標題、空 tagline、很多徽章 | 標題可截斷但完整名稱仍可被輔助科技取得；無空佔位文案，內容不重疊。 |
| C04 | P0 | 圖片載入失敗或尚未完成 | 保留圖片區域尺寸並顯示核准 fallback；不反覆請求失敗圖片。 |
| C05 | P0 | 掛載後改 variant / product-id 屬性 | 反映新變體或商品；無重複事件；未知商品有明確狀態。 |
| C06 | P0 | 設定 data property 後再更新 | 使用新資料重新呈現；不能因修改傳入物件而意外改寫其他卡片。property 與 attribute 優先序由 SPEC 定稿後驗證。 |
| C07 | P0 | 元件移除後重新接入 DOM 多次 | 恢復正常顯示；一次點擊僅觸發一次公開事件；離線期間取消訂閱與相關 listener。 |
| C08 | P0 | mount(container, options) → update → destroy | 可更新同一實例；destroy 移除該實例與訂閱，不清除容器內不屬於它的內容；重複 destroy 行為需定稿。 |
| C09 | P0 | 宿主設全域 img、button、p 樣式 | 卡片內部排版不受普通外部 selector 影響；卡片樣式不污染宿主。 |
| C10 | P0 | 宿主改 font / color 或公開 CSS custom property | 依明訂的繼承與主題契約呈現；不把 Shadow DOM 誤測為阻擋所有繼承或 CSS 變數。 |
| C11 | P1 | 模組重複載入／元件定義已存在 | 不因重複 customElements.define 讓頁面中斷。 |
| C12 | P1 | registry 註冊第三種測試變體 | 依核准 plugin API 可呈現，無須修改既有兩種變體；重複註冊規則須定稿。 |

## Showroom 與編輯器

| ID | 優先 | 情境 | 預期行為 |
|---|---|---|---|
| E01 | P0 | 進入列表後選擇商品 | 列表顯示全部 mock 商品；單卡預覽及表單與目前選取商品一致。 |
| E02 | P0 | 更改合法標題、價格、變體及選填值 | 依核准提交時機更新預覽與同商品列表；不改動其他商品。 |
| E03 | P0 | 輸入不合法價格或 URL | 欄位旁顯示可理解的錯誤；保留輸入供修正；不覆蓋最後合法的持久化資料。 |
| E04 | P0 | 清除選填欄位 | 預覽移除相關資訊；重新整理後仍為清除狀態。 |
| E05 | P0 | 切換商品再切回 | 已接受的編輯仍存在；未提交草稿如何處理依 SPEC 定稿，不可遺失而無提示。 |
| E06 | P0 | 空資料、讀取錯誤 | 顯示可理解的空／錯誤狀態，頁面仍可操作。 |
| E07 | P1 | 重設 mock | 依核准範圍還原資料；預覽、表單、儲存及其他分頁一致。 |

## Persistence 與狀態一致性

| ID | 優先 | 情境 | 預期行為 |
|---|---|---|---|
| S01 | P0 | 編輯後重新整理 | 從版本化 key 還原已接受資料；mock 不覆蓋有效儲存。 |
| S02 | P0 | localStorage 存在損壞 JSON 或不合法商品 | 安全降級並告知使用者；保留應用可用性，不直接 render 未驗證內容。 |
| S03 | P0 | 存取 localStorage 被拒絕或 quota 超限 | 記憶體操作繼續；明確顯示未保存狀態，不能宣稱已保存成功。 |
| S04 | P0 | 同 origin 分頁 A 修改；B 收到 storage event | B 依核准衝突策略更新；A 自己立即更新，不依賴不會在原分頁觸發的 storage event。 |
| S05 | P0 | 收到其他 key、移除 key、清除 storage 的事件 | 忽略無關資料；null 值事件依核准策略處理，不崩潰。 |
| S06 | P1 | 舊版資料或未來未知版本 | 僅支援明訂舊版 migration fixture；未知版本不假裝成功，不破壞既有儲存。 |
| S07 | P1 | 兩分頁近乎同時修改同商品 | 套用明確衝突規則並最終一致；有未提交草稿時的策略需 Gate 1 決定。 |

## 嵌入、可及性與畫面驗收

| ID | 優先 | 情境 | 預期行為 |
|---|---|---|---|
| I01 | P0 | 獨立 sample.html 載入 build 產物 | 不依賴 Showroom 啟動或 Vue／React runtime，即可宣告式呈現卡片。 |
| I02 | P0 | sample-mount.html 透過命令式 API | mount/update/destroy 可運作；不依賴全域內部狀態。 |
| I03 | P0 | Vue／React host 設定 data 與監聽公開事件 | 使用文件指定方式能更新資料並收到一次事件；以原生 ref/property + addEventListener 作為相容基線。 |
| I04 | P0 | Tab、Shift+Tab、Enter、Space 操作 | 表單與按鈕可操作、焦點可見；連結與按鈕語意正確，不產生巢狀互動控制。 |
| I05 | P0 | 螢幕閱讀器讀取卡片 | 圖片有適當替代文字、圖示動作有可辨識名稱；裝飾性圖示不重複朗讀。 |
| I06 | P0 | 無 videoUrl／productUrl | 不顯示會誤導的可用播放／導頁動作；實際行為須依定稿 API。 |
| V01 | P0 | Gate 2：第一張 ranking 卡截圖 | 人工比較參考圖的橫式資訊順序、圖片比例、粉紅價格、文字截斷與留白；記錄差異及接受理由。 |
| V02 | P0 | Gate 3：兩變體、列表、編輯器、sample | 截圖檢視字體、重疊、空值、長文、售完、錯誤圖片；不能只交測試通過報告。 |
| V03 | P1 | 375px 與桌面寬度 | 核心控制可使用，頁面無非預期水平溢出；不要求完整商業 RWD 打磨。 |

## Gate 1 待定規則

由 Planner 彙整到 QUESTIONS，QA 不自行核准：價格小數與折扣公式；未知變體策略；data/attribute 優先序；表單提交與切換草稿策略；跨分頁衝突／reset 策略；migration 支援來源；無 URL 的 CTA；公開事件名稱與 detail；重複 destroy 與 registry 規則。

## 執行紀錄規則

每次驗證記錄 case ID、結果、證據與 commit。失敗歸責 code / test / spec / env；同一 code 問題最多三次修正。測試變更由 QA 提出原因並遵循 WORKFLOW 人工裁決，不為符合實作而降低預期。現階段沒有執行結果，亦沒有宣稱測試通過。
